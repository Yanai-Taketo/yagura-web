# 広告（こうこく）の設けかた

Yagura のサイトに差し込む広告の仕組みと、その有効化の手順。

---

## 一、いまどうなっているか

**既定では、外部の広告は一切読み込まれない。**
`js/koukoku.js` の `SETTEI.client` が空だからである。
枠には代わりに Yagura 自身の案内（配布・企業導入ガイド・読みもの）が表示される。

AdSense の審査に通り、パブリッシャー ID を書き入れた時点で、
同じ枠がそのまま広告に切り替わる。**HTML を触り直す必要はない。**

---

## 二、置いた場所と、置かなかった場所

### 置いた場所 —— 読みもの（ブログ）だけ

| 頁 | 枠の数 | 位置 |
| --- | --- | --- |
| 読みもの一覧 `/blog/` | 1 | 目録の下 |
| 記事（本文 1,600 字未満）6 本 | 2 | 本文の区切りに 1・結びのあとに 1 |
| 記事（本文 1,600 字以上）4 本 | 3 | 本文の区切りに 2・結びのあとに 1 |

本文中の位置は、機械的な等分ではなく**話題の変わり目**を選んである。
「手順一・二・三」や「一. 送信側 → 二. 経路 → 三. 受信側」のような
連なりの途中を割ることはしていない。

### 置かなかった場所と、その理由

| 頁 | 理由 |
| --- | --- |
| トップ `/` | 絵巻（横巻き）の意匠が成り立たなくなる。かつ製品を判断する頁であり、広告は転換率を確実に下げる |
| 企業導入ガイド `/enterprise/` | 情報システム部門が稟議に添える検討資料。広告は資料としての信を損なう（刷る前提の頁でもある） |
| 特定商取引法の表記 `/tokusho/` | 法定の表記。広告を混ぜるべきでない |
| プライバシーポリシー `/privacy/` | 同上 |

読みものだけに絞るのは、収益を捨てる判断ではない。
検索から入ってくるのは記事であり、**広告を見るのは記事の読者だけ**である。
製品を検討している人に広告を見せても、収益は増えず、転換だけが減る。

## 三、有効化の手順

### 1. AdSense に申し込む

<https://adsense.google.com/> でサイト `yagura.ta-yan.ai` を登録し、審査を受ける。
審査には、プライバシーポリシーの掲示（`/privacy/` に用意済み）と、
一定量の独自コンテンツ（記事 10 本は要件を満たす）が要る。

### 2. 広告ユニットを四つ作る

AdSense の管理画面で「広告」→「広告ユニットごと」→「ディスプレイ広告」を選び、
**レスポンシブ**で四つ作る。名前は何でもよいが、対応が分かるようにしておく。

| 枠の名（コード側） | 用途 |
| --- | --- |
| `honbun-hajime` | 記事本文の前寄りの区切り |
| `honbun-naka` | 記事本文の中ほどの区切り |
| `kiji-shita` | 記事の結びのあと |
| `mokuroku-shita` | 読みもの一覧の末 |

作ると `data-ad-slot="1234567890"` のような数字が発行される。

### 3. `js/koukoku.js` に書き入れる

```js
var SETTEI = {
  client: 'ca-pub-0000000000000000',   // ← 自分のパブリッシャー ID
  waku: {
    'honbun-hajime':  '1234567890',    // ← 発行された数字
    'honbun-naka':    '2345678901',
    'kiji-shita':     '3456789012',
    'mokuroku-shita': '4567890123'
  },
  ...
};
```

書き入れなかった枠は、そのまま自前の案内であり続ける。
一部だけ有効にする、という段取りも取れる。

### 4. 自動広告（Auto ads）は切っておく

AdSense の管理画面で、このサイトの **「自動広告」を必ずオフ**にすること。

オンのままだと、画面下に貼り付く帯広告（アンカー広告）や、
画面全体を覆う広告（インタースティシャル）が Google の判断で勝手に挿入される。
横巻きのトップページに割り込む恐れもある。
——「利用者の負担にならない程度」という前提が、そこで崩れる。

### 5. `ads.txt` を置く

パブリッシャー ID が確定してから、`ads.txt.example` を参考に
リポジトリ直下へ `ads.txt` を置く。

**ID が確定するまでは置かないこと。** 誤った ads.txt は、無いよりも不利になる。

## 四、記事を書き足したときは

新しい記事の HTML に、次の三つを足すだけでよい。

1. `<head>` に意匠を読ませる

   ```html
   <link rel="stylesheet" href="../../css/blog.css">
   <link rel="stylesheet" href="../../css/koukoku.css">
   ```

2. `<body>` に紙面の根（相対パスの起点）を付ける

   ```html
   <body data-root="../../">
   ```

3. 枠を置き、末尾で読み込む

   ```html
   <!-- 本文中、話題の変わり目の <h2> の直前に -->
   <div class="koukoku" data-koukoku="honbun-naka"></div>

   <!-- 結び（.musubi）のあと、次の読みもの（.tsugi）の前に -->
   <div class="koukoku" data-koukoku="kiji-shita"></div>

   <!-- </body> の直前に -->
   <script src="../../js/koukoku.js" defer></script>
   ```

枠の中は**空のまま**にしておくこと（`css/koukoku.css` の `.koukoku:empty` が、
JavaScript が動かなかったときに場所を取らないようにしている）。

目安は本文 1,600 字までなら二つ、それ以上なら三つ。
`SETTEI.kagiri` が一つの頁の上限（既定 3）を機械的に抑えている。

## 五、読み手の負担を抑えている仕掛け

| 仕掛け | 中身 |
| --- | --- |
| 遅延読み込み | 枠が画面の 600px 手前に来るまで、外部への通信を一切しない。読まれなかった頁の広告のために通信は発生しない |
| 上限 | 一つの頁に三つまで（`SETTEI.kagiri`） |
| 高さの先取り | `.koukoku-ba` に最低の高さを取り、紙面が後から跳ねない（CLS 対策） |
| 空白を残さない | 広告が埋まらなかった枠（`data-ad-status="unfilled"`）は、自前の案内に差し替える |
| 遮断されても崩れない | AdSense が読めなかったときも、案内に差し替わるだけ。詰る表示や再読込の催促はしない |
| 通信量の節約 | `Save-Data` / `prefers-reduced-data` が有効な読み手には、外部の広告を読み込まない |
| 読み手の取りやめ | `?koukoku=off` で以後表示しない（`?koukoku=on` で戻る）。`/privacy/` に釦を置いてある |
| 刷るときは出さない | `@media print` で非表示。企業内で配る資料に広告は載らない |
| 札を付ける | 第三者の広告には「広告」、自前の案内には「案内」と明示（JIAA のガイドラインに沿う） |

---

## 六、全部やめるとき

`js/koukoku.js` の `SETTEI.client` を空文字列に戻せば、
外部への通信は止まり、枠は自前の案内に戻る。HTML はそのままでよい。

枠ごと消したい場合は、各 HTML の `<div class="koukoku" ...>` と
`<script src=".../koukoku.js">`、`css/koukoku.css` の読み込みを外す。

---

## 七、関わる決まりごと

- **プライバシーポリシー** —— `/privacy/` に掲示済み。AdSense の規約が求める
  「第三者による Cookie 利用の開示」と、無効化の案内を含む。
- **電気通信事業法の外部送信規律（第 27 条の 12）** —— `/privacy/` の
  「外部への情報送信について」の表が公表にあたる。送信先を増やしたときは、
  この表も併せて更新すること。
- **EU 圏からの閲覧** —— GDPR の同意取得が要る。AdSense の管理画面で
  「プライバシーとメッセージ」→ GDPR メッセージを有効にすること
  （Google の CMP が担う。こちら側の実装は要らない）。
